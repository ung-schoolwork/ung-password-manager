# Contributing

How the team works on this repository. Setup, architecture and deployment are in the [README](README.md).

## Workflow

1. Every change starts from a Jira ticket (`SCRUM-<number>`).
2. Branch from the latest `main` as `SCRUM-<number>-<short-slug>` (or `<your-name>/SCRUM-<number>/<short-slug>`).
3. Commit with the ticket in the subject, in the conventional-commit style the history uses:
   `feat(SCRUM-58): import .xlsx files and list each imported or failed row`. Use `feat`, `fix`, `test`, `docs` or `refactor`.
4. Open a pull request against `main` that names the ticket and says how the change was tested.
5. CI (`.github/workflows/ci.yml`) must pass: lint, unit tests, integration tests, type-check, the app and extension builds, and the Playwright suite on desktop and mobile Chromium. Green pull requests are merged with a merge commit.
6. Before merging, merge or rebase the latest `main` so the checks ran against what will land.

## Running the checks locally

Unit tests, lint and the type-check need nothing else:

```bash
bun install
bun run lint
bun run typecheck
bun run test
```

Integration and browser tests need a disposable MongoDB. The integration tests refuse to run unless `MONGODB_URI` points at a test database (the auth tests require `ung_auth_test`), so they cannot touch real data:

```bash
docker run --detach --name ung-auth-test --publish 127.0.0.1:27018:27017 mongo:8
export MONGODB_URI=mongodb://127.0.0.1:27018/ung_auth_test
export APP_ORIGIN=http://127.0.0.1:3100
export SHARE_ENCRYPTION_KEY=$(openssl rand -base64 32)
bun run test:integration
bun run test:e2e   # starts its own dev server on port 3100 and builds the extension it loads
```

Port 3100 must be free, and only one `next dev` can run per checkout, so stop your own dev server (or use a `git worktree`) before `test:e2e`.

## Where code goes

- `app/**/page.tsx` only renders a component; `app/api/**/route.ts` handlers stay thin and call into `lib/`.
- `lib/<area>/` holds the logic for `auth`, `devices`, `sharing` and `vault`. `client.ts` and `*.client.ts` files run in the browser (Web Crypto, browser storage, `fetch` to the API); `server.ts` and `*.server.ts` files run only on the server (Mongoose models, hashing) and must never be imported by a component. Other files hold validation and types that both sides share.
- `components/<area>/` holds React components by feature. `components/ui/` is generated by shadcn/ui; regenerate rather than hand-edit it.
- `extension/` is the Chrome extension. It reuses `lib/` modules through the bundler instead of copying them.
- Tests mirror the source: `tests/unit/<area>/` for `lib/`, `tests/integration/` for route handlers against a real database, `tests/e2e/` for the browser.

## API conventions

Route handlers answer with `json()` from `lib/auth/server.ts`, which sets `Cache-Control: no-store`.

| Status | When                                                                               |
| ------ | ---------------------------------------------------------------------------------- |
| 400    | The body is missing, too large, not JSON, or fails validation                      |
| 401    | No valid session                                                                   |
| 403    | The `Origin` is not the app or an allowed extension, or the device is not approved |
| 404    | The resource does not exist for this account                                       |
| 409    | Someone else changed it first (vault revision, password change, device removal)    |
| 410    | A shared credential has expired or was revoked                                     |
| 429    | Rate limited; `Retry-After` says when to try again                                 |
| 503    | Anything unexpected, through `failure()`, with a generic message                   |

- Every state-changing handler checks `originAllowed(request)` first; cookies are `SameSite=Strict` as a second layer against cross-site requests.
- Read request bodies with `readJsonObject` from `lib/http/json-body.ts`, which caps the size while streaming.
- Never return an exception's message, a stack trace or a database error to the client. Catch, map the known error classes to a status above, and fall back to `failure()`.
- Take the account from the session (`authenticatedUser`), never from a client-supplied ID.

## Writing for users

Text that users see in the app speaks to them only. Keep ticket numbers, sprint names, implementation or storage details and test wording out of rendered pages; put them in code comments, pull requests or Jira.

## Secrets

Never commit real credentials. Local settings go in `.env.local` (ignored by Git); `.env.example` lists every variable with safe defaults. The `SHARE_ENCRYPTION_KEY` in the CI workflow and Playwright config is a throwaway test key and must never be used for real data.
